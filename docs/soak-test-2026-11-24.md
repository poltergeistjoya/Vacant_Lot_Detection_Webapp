# Ramp soak test: 2026-11-24

**Command:** `./scripts/soak_test.sh ramp`

**Target:** `vacant-lot-app`, us-east1 (`./scripts/soak_test.sh ramp`, Locust, 5/20/50/100 users, 3 min each, 16:27-16:39 ET).

**Config:** 512Mi memory, 1 vCPU (default), 2 uvicorn workers, min instances 1, max instances 3, concurrency 80 (default).

## Results

Stage boundaries are approximate (from per-minute Cloud Run metrics). Latency is server-side p95; Locust's own client-side latencies were inflated by the laptop running out of CPU and are not used.

| Users | Requests/min | Server p95 | Worst-instance CPU | Instances |
|---|---|---|---|---|
| 5 | ~800 | 85-98 ms | 4-17% | 1 |
| 20 | ~2,500 | 93-123 ms | ~30% | 1 |
| 50 | ~3,200 | 300-361 ms | 38-41% | 1 -> 2 |
| 100 | ~3,100-3,400 | 110-225 ms | 14-29% | 2 -> 3 |

- 29,864 requests, 0 failures (all 2xx), 0.36 GiB downloaded (~$0.04 egress).
- Memory flat at 48-49% (~250 MiB of 512) for the whole run: no leak signal, but 256Mi would be too tight.
- Hit the 3-instance cap at 100 users; no requests rejected.

## Conclusion

512Mi / 2 workers / 1 vCPU is sufficient. CPU never neared saturation.

**Flat soak not run:** memory stayed flat across the 12-minute ramp, which is what a flat soak would check for.

Not tested: 1 worker vs 2.
